# Spec — Post drafting MVP

## Summary

Invited solo B2B consultants sign in and type a rough idea. One click turns it into three platform-ready drafts: a LinkedIn post, an X thread, and a Bluesky post. Each draft can be edited, regenerated, and copied to the clipboard. Nothing is published. The app quietly records generation and copy events so the founder can judge whether testers come back and post the drafts with only light edits.

## Goals

- **G1.** Let 5–10 invited testers go from rough idea to copy-ready drafts for three platforms in under a minute.
- **G2.** Produce drafts that follow the brand's writing rules: no generic hooks, no AI-sounding phrasing, the user's own wording kept.
- **G3.** Record enough usage data to answer two questions: do testers come back unprompted, and how much do they edit before copying?
- **G4.** Get the app in testers' hands by ~2026-11-25.

## Non-goals

- Voice input, style profiles, or style learning
- Publishing, scheduling, or connecting social accounts
- Images or media
- Admin dashboard, per-tester stats UI, or in-app draft ratings
- Asking clarifying questions when an idea is thin
- Version history for drafts
- Wiring the landing page waitlist signup, billing, or payments
- Platforms other than LinkedIn, X, and Bluesky

## Assumptions

Confirmed with the user on 2026-11-18:

- **Stack:** Next.js 16 App Router, React 19, Tailwind 4, Neon Postgres with Drizzle, deployed on Vercel.
- **Auth:** Neon Auth (Better Auth). Sign-up and sign-in are restricted to an email allowlist kept in a database table.
- **Users:** each user sees only their own posts. No teams, no sharing.
- **Generation:** one fixed prompt per platform, the same for every user, through Vercel AI Gateway. The model is set by an environment variable and defaults to a mid-tier writing model (`anthropic/claude-sonnet-5.5`, confirmed on AI Gateway on 2026-11-18).
- **Calls:** each platform is generated by its own call, all three run in parallel, and each streams into its own panel.
- **UI:** Ink & Paper tokens from `molten-docs/design/design.md`. Desktop-first, but usable on mobile.
- **Copy:** UI wording follows `molten-docs/brand/brand.md`. Output is always called "your draft".

## User stories

- **US-1.** As an invited consultant, I can sign in so that my posts are private to me.
- **US-2.** As someone who isn't invited, I'm told clearly that the app is invite-only, so I'm not confused.
- **US-3.** As a user, I see all my posts in one list, so I can pick up where I left off.
- **US-4.** As a user, I can start typing a rough idea as soon as I open the app, and generate drafts for LinkedIn, X, and Bluesky in one click.
- **US-5.** As a user, I can edit any draft, regenerate just one platform, and copy a draft to my clipboard to post it myself.
- **US-6.** As a user, I know when my drafts were generated from an older version of my idea.
- **US-7.** As a user, I can delete a post I no longer want.
- **US-8.** As the founder, I can query the database to see generations, copies, and how much users edited before copying.

## Functional requirements

**Access**
- **FR-1.** Users can sign in through Neon Auth with Google or a passwordless email method (a magic link or one-time code). There are no passwords.
- **FR-2.** Only emails in the `allowed_emails` table (matched case-insensitively) can create an account or sign in. Everyone else sees an invite-only message, and no account or session is created.
- **FR-3.** All app pages and APIs require a signed-in, allowlisted user. Signed-out visitors are sent to sign-in.
- **FR-4.** Users can sign out.

**Posts**
- **FR-5.** The **My posts** list shows only the current user's non-deleted posts, newest first. Each row shows:
  - an idea preview (first ~120 characters)
  - when the post was last updated
  - a status:
    - *Not generated*: the post has no drafts yet
    - *Draft*: drafts exist but none has been copied
    - *Copied*: at least one draft has been copied
- **FR-6.** The app opens on **Home**:
  - a writing box headed by a gentle nudge ("What's been on your mind this week?"), which serves as the **New post** action
  - below it, up to 4 of the user's most recently updated posts, shown as cards with the same preview, time, and status as FR-5
  - a link to **My posts**

  A user with no posts sees only the writing box. **My posts** has its own empty state that links back to Home.
- **FR-7.** Users create a post by typing a rough idea of 1–5,000 characters. Leading and trailing whitespace is trimmed, and an idea that is empty after trimming can't be generated.
  - The idea saves automatically within ~1 second of the user stopping typing.
  - The post is created the first time a non-empty idea is saved, whether by autosave or by Generate.
  - So an idea the user typed but never generated is kept, and shows as *Not generated* in the list.
- **FR-8.** Users can reopen a post to view or edit the idea and drafts.
- **FR-9.** Users can delete a post after a confirmation step. Deletion is a soft delete: the post disappears from the list and from direct URLs, but its events are kept.

**Generation**
- **FR-10.** **Generate drafts** saves the idea and then generates all three drafts in parallel, one call per platform. Each draft streams into its own panel as it is written. Generating from Home opens the post editor.
  - Once a post has drafts, the action is labelled **Regenerate all**.
  - Unedited drafts regenerate immediately.
  - Each edited draft first asks for confirmation in its own panel (FR-15) and is regenerated only if the user confirms.
- **FR-11.** Each platform has a fixed prompt that enforces the brand rules:
  - no engagement-bait or generic hook openers
  - no "As an expert…" phrasing
  - no emoji-bullet templates or hashtag stuffing
  - keep the user's phrasing and opinions
  - edit for clarity rather than to sound clever
- **FR-12.** Platform format targets:
  - **LinkedIn:** one post, ≤3,000 characters, short paragraphs.
  - **X:** a thread of 2–6 tweets, each ≤280 characters, numbered `1/`, `2/` and so on.
  - **Bluesky:** one post, ≤300 characters.
- **FR-13.** Each draft panel shows a live character count against its limit. For X, the count is shown per tweet. Going over a limit is highlighted but doesn't block editing or copying.
- **FR-14.** One platform failing doesn't affect the others. A failed panel shows a plain error with a **Try again** action for that platform only.
- **FR-15.** Each panel has **Regenerate**, which regenerates only that platform. If the user has edited that draft since it was generated, they must confirm first, because their edit will be replaced. The confirmation appears inline in the panel, not as a modal, with **Keep my edit** and **Replace it**.
- **FR-16.** While a platform is generating, its Generate and Regenerate actions are disabled, so the same platform can't run twice at once.
- **FR-17.** Each user can run at most 50 platform generations per rolling 24 hours (one Generate click counts as 3). Over the cap, generation is refused with a plain message saying when they can try again. The message counts in drafts, not platform generations, e.g. "You've used today's 50 drafts. You can generate again at 3:10 PM."

**Drafts**
- **FR-18.** Users can edit any draft inline. Edits save automatically within ~1 second of the user stopping typing, and also when the user copies.
- **FR-19.** Each panel has **Copy**, which copies the current draft text to the clipboard and shows a short "Copied" confirmation. An X thread is copied as all its tweets, separated by blank lines. Each tweet also has its own **Copy** button that copies just that tweet.
- **FR-20.** If the idea has been edited after a draft was generated, that draft shows a subtle note ("Your idea changed since this draft") with a Regenerate action. Drafts are never overwritten automatically.

**Signals**
- **FR-21.** The app records an event for each of these, with the user, post, platform (where relevant), model, and timestamp:
  - post created
  - generation started
  - generation completed
  - generation failed
  - draft copied
- **FR-22.** A *draft copied* event also stores the text as originally generated and the final text at the moment of copying. For a single-tweet copy, it also records the tweet number and stores that tweet's generated and final text.
- **FR-23.** No event ever shows its contents in the UI. The founder reads events directly from the database.

## Acceptance criteria (Given / When / Then)

**Access**
- **AC-1** Given an email in `allowed_emails`, when that person signs in with Google or with the email magic link or code, then they land on **Home** without ever setting a password. *(FR-1, FR-2, FR-6)*
- **AC-2** Given an email not in `allowed_emails`, when that person tries to sign up or sign in, then they see the invite-only message, no session is created, and no user row is created. *(FR-2)*
- **AC-3** Given an allowlisted email stored as `Jo@Example.com`, when someone signs in as `jo@example.com`, then access is granted. *(FR-2)*
- **AC-4** Given a signed-out visitor, when they request any app page or API, then pages redirect to sign-in and APIs return 401. *(FR-3)*
- **AC-5** Given a signed-in user, when they sign out, then they are returned to sign-in, and app pages are no longer reachable without signing in again. *(FR-4)*

**Posts**
- **AC-6** Given user A and user B each have posts, when A views **My posts** or requests B's post by URL or API, then A sees only their own posts, and B's post returns 404. *(FR-3, FR-5)*
- **AC-7** Given a user has three posts, when they view **My posts**, then the posts appear newest-updated first, each with an idea preview, last-updated time, and the correct status (*Not generated*, *Draft*, or *Copied*). *(FR-5)*
- **AC-8** Given a user has posts, when they open the app, then they land on Home with the writing box (headed "What's been on your mind this week?") ready to type in, and up to 4 recent posts below it. Given a user has no posts, then Home shows only the writing box, and **My posts** shows an empty state linking back to Home. *(FR-6)*
- **AC-8a** Given a user types an idea on Home and leaves without clicking Generate, when they open **My posts**, then the idea is there as a post with status *Not generated*, and exactly one *post created* event exists for it. *(FR-7, FR-21)*
- **AC-9** Given the idea field is empty or whitespace only, then Generate is disabled. Given the idea is over 5,000 characters, then the user sees a length message and Generate is disabled. *(FR-7)*
- **AC-10** Given a user deletes a post and confirms, then it disappears from the list, its URL returns 404, and its events still exist in the database. Cancelling the confirmation changes nothing. *(FR-9)*
- **AC-11** Given an existing post, when the user reopens it, then the latest saved idea and drafts are shown. *(FR-8, FR-18)*

**Generation**
- **AC-12** Given a valid idea, when the user clicks Generate, then the idea is saved and three panels (LinkedIn, X, Bluesky) start streaming text independently. Each panel shows its final draft when finished. Generating from Home opens the post editor. *(FR-10)*
- **AC-12a** Given a post with drafts where only the X draft has been edited, when the user clicks **Regenerate all**, then LinkedIn and Bluesky regenerate immediately, and the X panel shows the inline confirmation. **Keep my edit** leaves X unchanged with no model call, and **Replace it** regenerates X. *(FR-10, FR-15)*
- **AC-13** Given the sample ideas in the prompt-quality check (see Testing approach), when the drafts are generated, then none opens with a generic hook pattern ("Here's the thing", "Let's dive in", "Unpopular opinion:", a question-bait opener), none uses emoji bullets or more than 3 hashtags, and each keeps at least one distinctive phrase or opinion from the idea. *(FR-11)*
- **AC-14** Given the generated drafts, then the X draft is 2–6 numbered tweets, and the app parses them into separate tweets each with its own character count. The LinkedIn and Bluesky panels show counts against 3,000 and 300. *(FR-12, FR-13)*
- **AC-15** Given a draft goes over its platform limit, then its count is highlighted, and the user can still edit and copy it. *(FR-13)*
- **AC-16** Given the Bluesky call fails (e.g. a Gateway error or timeout) while LinkedIn and X succeed, then LinkedIn and X show their drafts, Bluesky shows a plain error with **Try again**, and a *generation failed* event is recorded. *(FR-14, FR-21)*
- **AC-17** Given an unedited LinkedIn draft, when the user clicks Regenerate on LinkedIn, then only the LinkedIn draft is replaced, and X and Bluesky stay unchanged. *(FR-15)*
- **AC-18** Given an edited draft, when the user clicks Regenerate, then a confirmation appears. Confirming replaces the draft, and cancelling keeps the edit. *(FR-15)*
- **AC-19** Given a platform is generating, then its Generate and Regenerate controls are disabled until it finishes or fails. *(FR-16)*
- **AC-20** Given a user has used 50 platform generations in the last 24 hours, when they try to generate again, then no model call is made, and they see a plain message saying when they can try again. *(FR-17)*

**Drafts**
- **AC-21** Given a user edits a draft and stops typing, when they reload the page about 2 seconds later, then the edit is still there. *(FR-18)*
- **AC-22** Given a draft, when the user clicks Copy, then the clipboard holds the current draft text and a "Copied" confirmation shows briefly. For X, the clipboard holds every tweet separated by blank lines. *(FR-19)*
- **AC-22a** Given an X thread, when the user clicks Copy on tweet 3, then the clipboard holds only tweet 3, and a *draft copied* event is recorded with tweet number 3 and that tweet's generated and final text. *(FR-19, FR-22)*
- **AC-23** Given drafts were generated, when the user then edits and saves the idea, then each existing draft shows the "Your idea changed since this draft" note with Regenerate, and no draft text changes. Regenerating a draft clears its note. *(FR-20)*

**Signals**
- **AC-24** Given a user creates a post, generates, regenerates one platform, and copies two drafts, then the events table has, for that post:
  - 1 *post created*
  - 4 *generation started*
  - 4 *generation completed*
  - 2 *draft copied*

  Each event carries the user, post, platform, model, and timestamp. *(FR-21)*
- **AC-25** Given a user edits a generated draft and then copies it, then the *draft copied* event stores both the original generated text and the edited final text. *(FR-22)*
- **AC-26** Given any page in the app, then no event contents or analytics are shown to users. *(FR-23)*

## Data model & API shape

Shape only. Exact columns, names, and indexes belong to mt-plan.

- **Auth tables:** managed by Neon Auth (Better Auth). App tables reference the auth user ID.
- **`allowed_emails`:** `email` (unique, stored lowercase), `note` (optional, e.g. the tester's name), `created_at`.
- **`posts`:**
  - `id`, `user_id`, `idea` (text)
  - `idea_updated_at`, `created_at`, `updated_at`
  - `deleted_at` (nullable, for soft delete)
- **`drafts`:** one per post per platform.
  - `id`, `post_id`, `platform` (`linkedin` | `x` | `bluesky`)
  - `content`: current text. For X, tweets are kept as an ordered list so per-tweet counts and blank-line-joined copy are exact.
  - `generated_content`: text as last generated.
  - `generated_at`, `updated_at`, `model`
  - Derived states:
    - *edited* when `content` ≠ `generated_content`
    - *stale* when `idea_updated_at` > `generated_at`
- **`events`:**
  - `id`, `user_id`, `post_id`, `platform` (nullable)
  - `type` (`post_created` | `generation_started` | `generation_completed` | `generation_failed` | `draft_copied`)
  - `model` (nullable)
  - `tweet_index` (nullable; set for a single-tweet X copy)
  - `generated_text` and `final_text` (filled for `draft_copied`)
  - `error` (nullable)
  - `created_at`
- **Rate limit (FR-17):** counted from `generation_started` events in the last 24 hours. No separate store is needed.

**Server surface (behavioural):**
- create, update, list, get, and soft-delete posts, all scoped to the current user
- **generate(postId, platform):** streams the draft text, persists it when finished, and records events
- **update draft(postId, platform, content)**
- **record copy(postId, platform, finalText)**

Whether each of these is a Server Action or a Route Handler is a decision for mt-plan, guided by the Next.js 16 docs in `node_modules/next/dist/docs/`.

## UX notes

- **Design system:** `molten-docs/design/design.md` (Ink & Paper). Newsreader serif for the idea and draft text; Geist sans for controls, labels, counts, and statuses.
- **Layout** (chosen in the prototype; see `molten-docs/prototype/post-drafting-mvp/hybrid.html`): start by writing, then a single-column editor. The same layout is used on desktop and mobile.
- **Screens:**
  - **Sign in:** Google and email.
  - **Invite-only notice.**
  - **Home** (the default route after sign-in):
    - the nudge as a serif heading
    - a large idea box with **Generate drafts**
    - "Recent" cards below (up to 4) and "All posts →"
  - **My posts:** the full list (FR-5), reached from the top bar and from Home.
  - **Post editor:** one column, max ~760px wide.
    - The idea is at the top, with its count and **Generate drafts** / **Regenerate all**.
    - Below it are LinkedIn, X, and Bluesky as stacked sections. Each has a serif heading, its format target, and its state.
    - A sticky strip under the top bar has **← My posts** and one link per platform showing its state. Clicking a link scrolls to that section.
    - **Delete post** is at the foot of the page.
- **Draft states**, shown as a dot and a label in the strip and in each section heading:
  - *Not generated*
  - *Writing…*
  - *Draft ready*
  - *Idea changed*
  - *Didn't finish*
- **Streaming motion:** text arrives a few words at a time, with a quiet "Writing your LinkedIn draft" label and a slowly pulsing dot. There is no caret and no typewriter effect, in line with `design.md`'s motion rules. Respect `prefers-reduced-motion`.
- **Confirmations:**
  - Regenerating an edited draft is confirmed inline in its panel.
  - Deleting a post uses a modal dialog.
- **Microcopy follows the brand:**
  - **Actions:** "Generate drafts", "Regenerate all", "Regenerate", "Copy", "Copy thread", "Try again", "Keep my edit", "Replace it", "Delete post".
  - **Statuses:** calm ("Draft ready", "Copied").
  - **Errors:** say what happened, then what to do next, with no jokes.
  - **Words to avoid:** "AI-generated" or "content" anywhere in the UI.
- **Success moment:** understated. "Copied" is enough; no confetti.
- **Invite-only message:** polite and plain, e.g. "Levercast is invite-only while we test it. If you think you should have access, reply to your invite email."

## Edge cases & error states

| Case | Expected behaviour |
|---|---|
| Email not on allowlist | Invite-only notice; no account or session (AC-2) |
| Session expires mid-edit | Unsaved draft edits are kept on screen; the next save shows "Please sign in again" and keeps the text so it can be copied |
| One platform's generation fails or times out | That panel shows an error and **Try again**; the others are unaffected (AC-16) |
| User leaves the page mid-stream | The partial result is discarded; the panel shows its previous draft or *Not generated* on return. *generation failed* is recorded if detectable |
| Model output breaks the format (e.g. X not numbered, over-length) | Shown as returned; counts are highlighted; X falls back to treating the whole text as one tweet if it can't be parsed |
| Model returns empty text | Treated as a failure (FR-14) |
| Rate limit reached | Plain message with the time it resets (AC-20) |
| Clipboard API blocked | Message: "Couldn't copy. Select the text and copy it manually." No *draft copied* event is recorded |
| Idea edited while drafts are generating | Drafts finish against the idea at the time Generate was clicked, then show the stale note |
| Idea typed on Home, never generated | Saved as a post with status *Not generated* (AC-8a) |
| **Regenerate all** with some drafts edited | Unedited drafts regenerate; each edited draft asks inline first (AC-12a) |
| Deleted post opened by URL | 404 |
| Very long idea (5,000 chars) | Accepted; Generate works |

## Non-functional requirements

- **Performance:** the first streamed text appears in each panel within ~3 seconds of clicking Generate (p50, normal Gateway conditions). **My posts** loads in under 1 second for a user with 100 posts.
- **Security and privacy:**
  - every query is scoped to the authenticated user (no IDOR)
  - the allowlist is enforced on the server, not only in the UI
  - the AI Gateway key stays on the server
  - no secrets are committed
  - the user's idea text is sent to the model only when they click Generate or Regenerate
- **Cost control:** per-user generation cap (FR-17); the model is set by environment variable.
- **Accessibility:**
  - WCAG 2.2 AA contrast, using the tokens already checked in `design.md`
  - every action can be done with the keyboard
  - focus states are visible
  - streaming panels use `aria-live="polite"`
  - the "Copied" confirmation and errors are announced
- **Reliability:** a failed generation never loses the idea or the previous draft.

## Testing approach

- **Unit (Vitest):**
  - character counting and limit checks
  - parsing X thread output into tweets
  - joining a thread for copy
  - derived states (edited, stale, post status)
  - rate-limit window maths
  - prompt builders (the brand rules are included)
  - allowlist email normalisation
- **Integration (Vitest against `TEST_DATABASE_URL`):**
  - post CRUD and soft delete
  - per-user scoping (AC-6)
  - allowlist enforcement
  - event recording for generate and copy (AC-24, AC-25)
  - rate-limit refusal (AC-20)
  - all of these use a mocked model so the tests are deterministic and free
- **End-to-end (Playwright):** one happy path covering:
  - sign in as an allowlisted test user
  - create a post and generate, using a mocked model
  - edit, regenerate, copy, delete

  Plus a check that a non-allowlisted user is blocked.
- **Manual prompt-quality check (gates inviting testers):**
  - The founder supplies 5 real rough ideas.
  - Generate drafts for all three platforms and compare them side by side with ChatGPT given the same ideas.
  - Check them against AC-13.
  - Iterate the prompts until the founder would post the drafts with light edits.
  - Record the results in the verify doc.
- **Manual:** keyboard-only pass and a narrow-viewport pass of the post editor.

## Boundaries

- **Always:**
  - Scope every data access to the current user.
  - Read the relevant Next.js 16 doc before writing framework code.
  - Follow brand microcopy rules.
  - Use conventional commits.
  - Keep the app runnable after each slice.
- **Ask first:**
  - adding dependencies beyond the expected set (AI SDK, Neon Auth/Better Auth client, Vitest, Playwright)
  - schema changes beyond the shapes above
  - changing the default model
  - changing platform limits or the rate cap
  - deleting or rotating env vars in Vercel
- **Never:**
  - publish or post to any social platform
  - auto-overwrite a user's edited draft
  - show "AI-generated" labels
  - commit secrets or `.env.local`
  - send idea text anywhere except AI Gateway
  - hard-delete events

- Email sign-in is passwordless (magic link or one-time code).
- X has per-tweet Copy, logged with the tweet number.

**Resolved by the prototype, 2026-11-18** (see `molten-docs/prototype/post-drafting-mvp.md`):
